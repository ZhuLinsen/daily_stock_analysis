Best suited for developers, debugging models and data sources locally, or running local `Ollama` models.

## Environment Setup

Requires **Python 3.10+** (Python 3.11 or 3.12 recommended). Launching the WebUI (`--serve` / `--serve-only`) from a source checkout also requires **Node.js `>=20.19.0 <27`** and **npm `>=10`** (unless prebuilt `static/` assets are already present):

```bash
git clone https://github.com/ZhuLinsen/daily_stock_analysis.git
cd daily_stock_analysis

python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1

pip install -r requirements.txt
cp .env.example .env
# Edit .env: set STOCK_LIST and at least one AI API key (see Minimal Env Config / LLM Configuration Guide)
```

Before running your first analysis, configure a valid AI API key following [Minimal Environment Configuration](/en/docs/getting-started/env-config/) or the [LLM Configuration Guide](/en/docs/configuration/llm-guide/) (a blank copy of `.env.example` works for `--doctor`, while analysis runs require a configured model).

## Common CLI Commands

```bash
# 1. Offline health diagnostics (no LLM calls; checks environment, dependencies, key formats, and source readiness)
python main.py --doctor

# 2. Run a full analysis and push notifications using STOCK_LIST from .env
python main.py

# 3. Analyze specific tickers only (add --no-market-review because MARKET_REVIEW_ENABLED defaults to true)
python main.py --stocks 600519,hk00700,AAPL,2330.TW --no-market-review

# 4. Run full analysis + market review with verbose debug logs (suppresses outgoing notifications only)
python main.py --debug --no-notify

# 5. Stock-pipeline dry-run without LLM market review or outgoing notifications
python main.py --dry-run --no-market-review --no-notify

# 6. Generate market review only
python main.py --market-review

# 7. Start the local scheduled daemon mode
python main.py --schedule

# 8. Start WebUI + API service without running immediate startup analysis (still restores saved schedules when SCHEDULE_ENABLED=true; default http://127.0.0.1:8000)
python main.py --serve-only
```

Note: `--dry-run` only skips LLM calls and notifications inside the stock pipeline. Because `MARKET_REVIEW_ENABLED` defaults to `true`, pass `--no-market-review` (and `--no-notify` to suppress outgoing pushes) whenever you only want to analyze specific tickers or verify data fetching and logs without invoking market-review LLM generation or notifications.

:::note[WebUI Frontend Build Prerequisite]
When running `python main.py --serve` or `--serve-only` from a source checkout, DSA auto-builds `apps/dsa-web` into `static/` on first launch if **Node.js `>=20.19.0 <27`** and **npm `>=10`** are available (or reuses prebuilt `static/` assets). Without either, the FastAPI backend starts normally, but opening `/` serves a `Frontend Not Built` page.
:::

## Optional MCP Stdio Server

DSA provides an experimental stdio MCP server (optional dependency `mcp>=1.0.0,<2`, kept out of core `requirements.txt`) to expose market quotes, analysis history, research context, and bounded analysis orchestration to external AI coding or desktop agents:

```bash
pip install "mcp>=1.0.0,<2"
python -m src.mcp_server
# Optional: include fxmacrodata_* tools
# python -m src.mcp_server --include-macro
```

By default, it exposes `ToolSurface` tools marked `read_only=True` plus `resolve_stock`, `start_stock_analysis`, `get_analysis_status`, and `get_latest_report`, while keeping `get_portfolio_snapshot` and all config-write tools disabled. Note that `start_stock_analysis` is **not purely read-only**: it consumes LLM model quota and persists a local analysis report (defaulting to `notify=False` so automated clients do not broadcast notifications), and some quote/search tools may refresh local caches. See the [Full Guide MCP Server section](/en/docs/reference/full-guide/#read-only-mcp-stdio-server-optional) for client configuration details.
