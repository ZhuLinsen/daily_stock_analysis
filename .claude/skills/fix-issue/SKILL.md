# 修复 Issue

遵循仓库根目录 `AGENTS.md` 的基线同步、目录边界和验证矩阵。

1. 阅读 Issue、最新讨论及已有的 `.claude/reviews/issues/issue-<number>.md`。核对当前基线能否复现、根因及验收条件。记录缺失的环境或外部服务证据。
2. 查清同一行为的运行入口、配置和消费方，再修改代码。按真实反例验证，覆盖适用的 CLI/API、Web/Desktop、报告、通知和降级路径。
3. 同步受影响的使用文档；新增或改变环境配置时更新 `.env.example`。PR 标题、标签和描述说明用户影响及升级操作，发布说明由发布流程生成。
4. 记录改前/改后、验证结果、风险和回滚。可见界面或报告变化附与当前 Head 对应的截图或替代可视证据。将结果补充到本地 Issue 分析记录。
5. 用户要求提交 PR 时，按 AGENTS.md 的授权和安全同步规则执行。关联 Issue，写清实际解决的范围；阶段性交付用 `Refs` 保留后续跟踪。
