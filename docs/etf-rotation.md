# ETF 轮动（规则化双动量）

`python main.py --etf-rotation` 基于一组事先定好的 ETF，输出**最新调仓信号**和**规则回测报告**。整个流程是纯规则计算，不调用 LLM，不依赖任何 AI 配置。

## 规则

1. **调仓日**：每周（或每月）最后一个交易日收盘后计算信号，下一个交易日收盘执行，避免使用信号当天的价格成交（防未来函数）。
2. **相对动量**：按过去 `ETF_ROTATION_LOOKBACK_DAYS` 个交易日的涨幅，对风险池中的 ETF 排名。
3. **绝对动量**：只有涨幅为正的 ETF 才能入选。每个名额占 `1/ETF_ROTATION_TOP_N` 仓位，没选满的名额转到防守资产 `ETF_ROTATION_SAFE_ASSET`；防守资产未配置或不可用时，按现金（收益为 0）处理。
4. **换仓缓冲**：已持有的 ETF 只要仍然合格，且动量落后最后一个入选名额不超过 `ETF_ROTATION_SWITCH_BUFFER_PCT` 个百分点，就继续持有，用来减少来回切换。
5. **只在组合变化时交易**：入选组合不变时不做任何交易，漂移后的权重也不会被重新拉回等权。
6. **交易成本**：每次调仓按 `换手率 × ETF_ROTATION_COST_BPS` 扣除。换入、换出现金不计换手。

计算仅接受明确采用前复权的 A 股 ETF 数据路径：Efinance、AkShare、Baostock，以及配置为 `forward` 的 TickFlow，保持这些来源原有的优先级和失败切换。Tushare、Pytdx、未前复权的 TickFlow 不作为本命令的兜底；没有合格来源时明确告警并剔除标的，不把未复权价格当成可用数据。调用方注入行情服务时，返回的 DataFrame 必须声明 `attrs["price_adjustment"]="forward"`。这些限制只作用于 ETF 轮动，不修改普通股票分析的数据源链。

风险池中尚未上市或历史不足的 ETF，在积累够 `LOOKBACK` 天数据之前不参与排名。短缺口仅为动量计算前填最多 5 根，当前没有真实有效收盘价的 ETF 不参与当日排名；参数扫描与主回测使用同一原始行情，不重复填补。

缺报价日不能买入或卖出，需交易的标的没有当日有效报价时跳过该次调仓，保留原持仓，等待后续计划调仓日。持仓在缺口期间按最后有效报价估值；恢复报价时计入相对于最后报价的完整涨跌，不把亏损吞掉。防守 ETF 在执行日没有报价时，空缺仓位保持现金；已有防守持仓缺报价时也不能虚构卖出。防守 ETF 最新没有报价，报告目标显示现金，并告警其不可用。该目标不保证下一个交易日可成交。

数据截止到最近一个**已收盘**的 A 股交易日：盘中运行时，当天未收盘的 K 线会被丢弃。

行情按真实 A 股交易日历对齐到该截止日，保留所有标的同时缺报价的交易日（包括末尾缺口），不把周末或节假日当作交易日。周一缺报价不会把上周的买入顺延到周二；周五缺报价也不会提前到周四产生周末信号。历史交易日历不可用或超出支持范围时明确报错，停止生成轮动报告，避免用报价日期代替交易日历。

## 使用

```bash
python main.py --etf-rotation              # 生成报告并按已配置渠道推送
python main.py --etf-rotation --no-notify  # 只生成本地报告
```

报告保存在 `reports/etf_rotation_YYYYMMDD.md`（日期取数据截止交易日，包括末尾缺报价日），包含以下内容：

| 章节 | 内容 |
| --- | --- |
| 数据告警 | 取数失败、历史被截断、单日异常涨跌（疑似拆分或复权缺失）、多个数据源混用 |
| 最新信号 | 当前规则持仓、按最新收盘计算的目标持仓、是否需要调仓，以及动量排名。最新收盘不是本周（本月）最后一个交易日时，目标持仓只作参考；交易日历不可用时会注明无法确认 |
| 回测表现 | 策略与"风险池等权持有（日再平衡、不扣成本）"对比累计收益、年化收益、波动、夏普（无风险利率取 0）、最大回撤、Calmar。两条曲线都从策略首次建仓日起算 |
| 分年度收益 | 逐年与等权基准对比，首尾两年可能不是完整年度 |
| 参数平原检验 | 只改变动量窗口（20 到 200 日，并始终包含当前配置的窗口），在统一区间内对比年化收益、回撤和夏普；会让统一区间不足 1 年的窗口不列出 |
| 近期调仓记录 | 最近 10 次调仓的信号日、执行日、调出和调入 |

可回测区间（从首次建仓日到最新收盘）不足 1 年时，年化类指标没有参考意义，报告只保留数据告警、最新信号和规则说明，并在告警里说明原因。

建议用 cron 或 CI 在每周最后一个交易日收盘后运行一次。本命令不接入 `--schedule`。

## 配置

以下配置都是可选的，不配置时使用默认值。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ETF_ROTATION_POOL` | `510300,510500,159915,512890,513100,518880` | 风险池，逗号分隔，会自动去重。默认依次为沪深300、中证500、创业板、红利低波、纳指、黄金 |
| `ETF_ROTATION_SAFE_ASSET` | `511880` | 防守资产（货币 ETF）；配置为空表示持有现金 |
| `ETF_ROTATION_LOOKBACK_DAYS` | `60` | 动量窗口（交易日），取值范围 5 到 500 |
| `ETF_ROTATION_REBALANCE` | `weekly` | `weekly` 或 `monthly`，填写非法值时回退为 `weekly` |
| `ETF_ROTATION_TOP_N` | `2` | 最多同时持有几只，取值范围 1 到 10 |
| `ETF_ROTATION_SWITCH_BUFFER_PCT` | `2.0` | 换仓缓冲（百分点） |
| `ETF_ROTATION_COST_BPS` | `10` | 单边交易成本（bp），包含佣金和滑点 |
| `ETF_ROTATION_BACKTEST_YEARS` | `8` | 回测拉取的历史年数，取值范围 1 到 30 |

这些配置只在命令行中生效，没有进入 Web 设置页。

## 解读与边界

- **先看参数平原，再看收益**。如果相邻窗口之间收益差异很大，说明当前参数的结果主要来自运气。持有 1 只时路径依赖最强，所以默认持有 2 只。
- 趋势轮动的主要价值是**控制回撤**，并不保证跑赢基准。在震荡市里它会反复止损；遇到急涨行情（比如跳空的连续涨停）时反应会滞后。回测跑输等权持有是常见的正常结果。
- **池子要事先定死**。回测时事后挑选"涨得好的 ETF"会产生幸存者偏差。
- **数据源回退可能静默截断历史**。例如东财接口不可用时回退到 Baostock，可能只返回最近一段数据。这种情况会在"数据告警"中列出，此时回测区间会变短，结论要打折扣；不足 1 年时回测部分会直接省略。
- 报告保存或推送失败只记录告警日志，不影响命令退出码；单只 ETF 取数失败或返回格式异常时，会从本次计算中剔除并列入数据告警。
- 回测结果不代表未来收益，不构成投资建议。

## 实现位置

- `src/core/etf_rotation.py`：纯逻辑，包括信号、回测、指标和参数扫描，不做任何 I/O
- `src/services/etf_rotation_service.py`：取数、数据告警、报告渲染和推送
- `tests/test_etf_rotation.py`：规则、防未来函数、成本、告警和配置解析的测试
