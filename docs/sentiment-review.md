# 每日情绪复盘

Web 侧边栏的“情绪复盘”是独立的收盘后功能。点击“启动今日复盘”会计算最近一个已完成交易日；现有定时分析任务也会自动调用一次。数据库以 `market + trade_date` 保证每天只有一条记录，重复启动直接返回已有结果，除非 API 显式传入 `force=true`。

## 复盘清单

- 市场宽度：上涨、下跌、平盘家数，涨跌家数差，全市场成交额及相对上一交易日变化。
- 涨停生态：涨停家数、炸板家数、炸板率、最高板、各高度板数。
- 晋级表现：2板、3板、4板及以上晋级率。
- 昨日涨停反馈：今日集合竞价收益率和收盘收益率的中位数、样本标准差、红盘率。
- 题材强度：按涨停个股所属行业统计并排序。
- 情绪状态：仅当历史样本和核心数据完整时按固定阈值分类；样本不足显示为空。
- 文字复盘：LLM 只生成“行情分析、次日观察方向、风险提示”，不能写回或修改规则指标。

## 计算规则

- 涨跌家数差 = 上涨家数 - 下跌家数。
- 成交额变化 = 当日成交额 / 上一交易日成交额 - 1；分母为 0 或缺失时为空。
- 炸板率 = 去重后的炸板家数 /（收盘涨停家数 + 炸板家数）。
- 2板晋级率 = 今日2板数 / 昨日1板数。
- 3板晋级率 = 今日3板数 / 昨日2板数。
- 4板及以上晋级率 = 今日4板及以上数 / 昨日3板及以上数。
- 昨日涨停竞价收益 = 今日开盘价 / 昨日收盘价 - 1。
- 昨日涨停收盘收益 = 今日收盘价 / 昨日收盘价 - 1。
- 历史分位 = 历史窗口中小于等于当日值的样本数 / 有效样本数；少于20个有效样本不输出正式分位。
- 所有比率在数据库中保存为小数，Web 展示时转换为百分比。缺失值保持 `null`，曲线不补 0。

## 数据来源与质量

AkShare 是主数据源。配置了 `TUSHARE_TOKEN` 时，Tushare 可在 AkShare 市场宽度接口失败时补充指定交易日的涨跌家数和成交额；涨停、炸板和晋级证据仍以 AkShare 为主。记录质量分为 `complete`、`partial`、`imported`，导入记录不能覆盖完整计算记录。

历史曲线默认随每日复盘积累。对雪球文章等公开来源整理出的近30日数据，应先人工核验并转换为 JSON 数组，再受控导入：

```powershell
conda run -n daily_stock python scripts/import_sentiment_review_history.py history.json
```

每项格式为 `{"trade_date":"2026-06-26","source":"xueqiu_verified","payload":{...}}`。不在生产运行时直接依赖雪球页面，避免登录态、反爬变化或文章口径变化造成每日任务失效。

## 配置

- `SENTIMENT_REVIEW_ENABLED=true`：启用定时复盘；关闭后手动 Web 启动仍可使用。
- `SCHEDULE_ENABLED`、`SCHEDULE_TIME(S)`：沿用项目现有定时任务配置。
- `TUSHARE_TOKEN`：可选增强，敏感值仅从现有配置读取，不写入日志或复盘数据。
